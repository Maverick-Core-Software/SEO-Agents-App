## Findings (observed facts)

### 1. Facebook Graph adapter — `scripts/facebook-poster.mjs`
- **Approval gate**: single-payload mode requires `payload.live === true` and no `--dry-run` (`runSinglePayload`). Weekly mode gates on `--dry-run` only; row-level approval lives upstream (mav-bridge claims `weekly_posts` rows with `status='approved'`, `scripts/mav-bridge.mjs:304-324`); Python path gates via `approval_required` + dispatch gate (`src/seo_agents/actions.py:1447-1451`).
- **Idempotency**: none at the Graph-create level — no dedupe key is sent and no pre-check "already posted today" exists. Only the first-comment is idempotent (state file `state/fb-first-comments.json` + Graph read `hasContactFirstComment`, `facebook-poster.mjs:214-330`). Python layer dedupes on prior `live_complete` run records keyed by (action_id, idempotency_key) (`actions.py:2344-2390`).
- **Verification**: `--check-token` validates `FB_PAGE_ACCESS_TOKEN` via `/debug_token` with expiry classification (`classifyDebugToken`); post creation returns the Graph post id (server-acknowledged). No post-hoc read-back of live single posts in the poster itself; `fb-reconcile` in mav-bridge (mav-bridge.mjs:563-612) verifies scheduled posts by GET-ing the post object and retries first comments.
- **Retry**: `withTokenRetry` retries once on Graph codes 190/102 after re-resolving the Page token (facebook-poster.mjs:640-660); first-comment retries 3-6× with backoff; main post dispatch has no retry.
- **Rollback**: none in code (deletion is manual). `scripts/reset-facebook-posted.mjs` flips `error→posted` for dates (guarded `.eq('status','error')`), requires `SUPABASE_SERVICE_KEY`.
- **Credentials**: `FB_PAGE_ID`, `FB_PAGE_ACCESS_TOKEN`/`FB_ACCESS_TOKEN`, `XAI_API_KEY`/`GROK_API_KEY`, `GEMINI_API_KEY` — all from repo `.env`; the loader **force-overrides** inherited env (documented: PM2 inherits MCC's `.env`). Server-side only (spawned by mav-bridge/PM2 or CLI). Optional Playwright fallback (`FB_USE_PLAYWRIGHT=1`) uses session dir `~/.claude/fb-session`, headful.
- Related: `scripts/facebook-insights-collector.mjs` is read-only analytics; on missing creds or API failure it writes a fallback report (`ok:true, mode:'fallback'` on missing creds, `ok:false` on API error). `scripts/video-postprocess.mjs` degrades gracefully (copies raw on any ffmpeg failure). `scripts/xai-video-generator.mjs` polls up to 12 min, has `--dry-run`, `XAI_API_KEY` from `.env` (force-override loader); no retry — the poster falls back to photo/text.

### 2. GBP browser adapter — `scripts/gbp-poster/driver.mjs` (+ `gbp-worker.mjs`, `gbp-post-once.mjs`, `verify-gbp-posts.mjs`)
- **Approval gate**: workbook `Status === 'Approved'` else exit 4 (`needs_approval`); content-policy gate `checkPostPolicy` exit 5 (phones/URLs/addresses/banned words — `policy-check.mjs`, added after the 2026-07-31 profile-wide rejection); weekly approval propagated by `mark_gbp_dates_approved` / `sync-gbp-schedule --approve-dates`. Worker claims rows via atomic CAS `approved→posting` (gbp-worker.mjs:105-120).
- **Idempotency**: refuses if workbook `Posted` is true; duplicate guard `submitted` flag — once the Post button is clicked, never re-submitted (`POST_ATTEMPTS=2` applies only pre-submit; driver.mjs comment "Once the Post button is clicked we NEVER retry").
- **Verification**: inline `verifyPosted` (5 attempts × 60s, snapshots to `outputs/gbp-debug/`); scheduled posts treat composer-close as confirmation. Retro-verification: `verify-gbp-posts.mjs` (14-day lookback, matches caption snippet, writes `platform_post_id` — placeholder `'verified-no-url'` when no URL) + worker verify queue (10 min initial delay, then 15 min × 4 attempts; confirmed/crash/miss disposition via `gbpVerifyDisposition`).
- **Retry**: only `ui_changed_or_timeout` is retryable, pre-submit, max 2. `session_expired`/`captcha` are human-blocking by design (selfcheck pins this precedence).
- **Rollback/reset**: no unpost; `scripts/reset-gbp-scheduled.mjs` resets GBP rows to `scheduled` with **no status filter** (can reset `posted` rows → re-post risk if run with wrong dates); it also logs `row.topic` which is not in the `.select()` (undefined). `markGbpPostedAndArchive` (lib/gbp-runner.mjs) sets workbook `Posted=TRUE` (Excel lock retry 6×5s) and archives the photo to `GBP_ARCHIVE_FOLDER`.
- **Credentials**: no API token (Playwright session `C:\Users\carte\.claude\gbp-session`); worker uses `SUPABASE_URL`+`SUPABASE_SERVICE_KEY` (don't-clobber env loader). gbp-worker runs as user `carte` via Windows Scheduled Task (header comment); mav-bridge GBP path is off by default (`MAV_BRIDGE_GBP=off`) to prevent double-posting.
- Exit-code contract (shared with callers): 0=posted+verified, 3=unverified, 4=needs_approval, 5=policy_violation, else=error; abnormal exits (>255/negative) map to needs_verification, never to retryable (`gbpDailyStatusForExit`, `gbpScheduleStatusForExit` — exit-3 never falls back to `scheduled`).
- **Stuck-state recovery**: mav-bridge.mjs:697-713 resets any `posting` row older than 30 min to `error` (both platforms).
- Note: `gbp-post-once.mjs` is a hardcoded one-shot (baked caption+image) with no approval gate, no policy gate, and it prints `{result:'posted', verified:true}` with no verification performed.

### 3. Website adapter — `src/seo_agents/website.py`
- **Approval gate**: none inside the adapter; `live` flag + approval_class from actions.py (mandatory for layout/contact-form, sampled for others). Dry-run writes previews to `outputs/website_preview/`.
- **Idempotency**: none — `apply_edit` writes files, `git pull --rebase`, commit+push only touched files; branch guard (`master` expected). Blog re-run with identical content → `git commit` fails ("nothing to commit") → status `error` → `adapter_failed` (no graceful dedupe).
- **Verification**: pre-commit `validate_index` (tag balance vs original, section disappearance, size shrink) and `build_blog_files` checks; post-push verification none (push triggers Vercel; deploy not checked). `push_failed` → `live_unverified`.
- **Retry/rollback**: none automated; rollback is manual git revert.
- **Credentials**: no secrets in module; push uses ambient git credentials. `WEBSITE_REPO_DIR` env.
- **Defect (confirmed)**: `website.py:147` — `re.sub(r"\s*```\s*$", "", "", stripped)` passes `stripped` (a str) as `count` → `TypeError` whenever input starts with a code fence. LLM website edits are frequently fenced; `apply_edit` calls `strip_fences` on `html` (website.py:319) and on blog body. The exception is not caught in `run_action` → unstructured crash instead of an `adapter_failed` record (lock is released by `enforce_idempotency`'s `finally`).

### 4. Python action layer — `src/seo_agents/actions.py`
- Dispatch gate (12 checks: run-id freshness, task-graph status, claim validity, contradictions, approval, adapter presence, idempotency key) runs before every adapter call; failures recorded as `gate_blocked` without invoking adapters.
- `enforce_idempotency` (actions.py:2344+): prior `live_complete` record with same key → dedupe; atomic reservation via `O_CREAT|O_EXCL` lock file `outputs/action_runs/.lock-{action_id}`; released in `finally`. **No TTL/cleanup for stale locks** (grep of repo: only actions.py references `.lock-`).
- GBP result mapping: exit 0+verified → `live_complete` + workbook marked Posted; exit 3 / posted-unverified → `live_unverified` ("check manually before retry", never auto-retried). FB: exit 0 + `status==='success'` → `live_complete`.
- Failure classification (`classify_review_failure`): `needs_verification` outranks `transient_retry`; "timeout" text → `transient_retry` recovery requeue.
- Tests: `tests/test_idempotency.py`, `test_dispatch_gate.py`, `test_failure_classification.py`, `test_phase5_integration.py`, `test_run_action_cli.py` cover the Python paths (mocked adapters). No test mentions stale locks (grep `lock|stale` in tests → none). JS selfchecks: `facebook-poster.selfcheck.mjs` (token classification, caption, schedule parse), `gbp-poster/driver.selfcheck.mjs` (classifyFailure precedence only).

## Analysis (inference)

**Transitions UNTESTED or UNHANDLED:**

1. **Stale idempotency lock (crash-after-claim, Python path) — UNHANDLED.** A hard crash during a live `run_action` leaves `.lock-{action_id}` forever; every later live call returns the `concurrent_retry` placeholder. No TTL, no cleanup, no test.
2. **Post-success-before-write (FB, both paths) — UNHANDLED.** Graph create succeeds, then process dies before the run record / Supabase update. Dedupe keys only off `live_complete` records; re-run duplicates. Same window via subprocess timeout: `FACEBOOK_POSTER_TIMEOUT_S=900` vs up-to-13-min video gen + comment retries is tight; a 124 exit after a successful post classifies as `transient_retry` and requeues → duplicate. mav-bridge's parse-failure path (mav-bridge.mjs:373-377) makes it worse: if per-day results can't be parsed it marks **all** `posting` rows `posted`, and the unmapped-days fallback (lines 369-372) marks leftovers posted — false-positive posted rows that fb-reconcile never rechecks (it only inspects scheduled rows by post id).
3. **Crash windows (GBP) — PARTIALLY HANDLED.** Clean path is well guarded (submitted-flag, exit-3 never → scheduled, workbook Posted gate). But between driver success and `applyDriverResult`/`markGbpPostedAndArchive`, neither Supabase nor the workbook is updated; the 30-min TTL resets the row to `error`, and the dashboard retry for GBP sets `scheduled`, which the same-day daily cron re-runs → **duplicate GBP post**, because the driver does no pre-submit "already visible today" check. Only the human-facing error strings say "check before retry".
4. **Duplicate resume (FB week batch) — UNHANDLED.** `runWeek` parses `STATUS` from the schedule but never uses it to skip posted days; all days are claimed to `posting` before the batch runs. Mid-batch crash → TTL resets everything to `error` → retry re-posts days already live. Remediation is manual (`reset-facebook-posted.mjs` covers the opposite direction only).
5. **Expired auth — HANDLED.** FB: token-error classification restricted to codes 190/102, one retry after page-token exchange, `--check-token`, selfchecked. GBP: three `assertLoggedIn` variants + interstitial detection, human re-auth by design. xAI/Gemini: pre-flight credit check, per-post fallback to photo/text.
6. **Website fence bug — defect** (`website.py:147`) converts a routine LLM formatting quirk into an unstructured crash on the live path; duplicate blog resume surfaces as `adapter_failed` rather than a dedupe hit (minor).

**Other observations (low severity):** `reset-gbp-scheduled.mjs` lacks a status guard (can un-post rows by mistake) and logs an unselected field; actions.py GBP paths default to skill/plugin copies outside the repo (`~/.claude/skills/gbp-poster/driver.mjs`, `~/.codex/plugins/.../config.local.json`) while gbp-worker uses the repo copy — drift risk between two driver.mjs copies; `gbp-post-once.mjs` asserts `verified:true` without verification; FB claim in mav-bridge doesn't use `.select()` to confirm CAS success (safe only while single-instance).
